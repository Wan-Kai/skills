# 布局与路由

## 先定页面

每页只表达一个抽象层级：领域地图、实体关系、流程或架构。先用领域地图定边界；对象细节、流程机制和 UI 载体分别另页。若读者必须同时理解两层，使用概览页加链接/编号，而不是把两层塞进同一画布。

编辑已有图时，先确认本地 XML 与浏览器画布的保存状态。小范围样式、文案或单节点调整可原位 patch；改变层级、容器或多条跨域边时，先复制为相邻的 `*-before-reflow.drawio` 或新页面，得到确认后才替换原页。浏览器中未保存的改动只能由用户先保存/下载后再合并。

## 坐标草图

写 XML 前，在回复或工作笔记中列出：

| 项目 | 必填内容 |
| --- | --- |
| 页面 | viewport、侧栏占用、可用宽高、目标 overview/detail 缩放 |
| 容器 | 根坐标 bbox、标题安全区、容器间 gutter |
| 节点 | ID、父容器、根坐标 bbox、端口侧 |
| 边 | source/target、跨域与否、标签位置、waypoint 根坐标 |

以目标浏览器 viewport 规划，而非持续拉宽画布：左右边缘各留约 40px，侧栏打开时预留其占用；若 overview 下左右域被裁切，拆页或缩减内容。优先让页面在 35–45% overview 与 65–80% detail 都可用。

## 跨域走廊

把容器之间的空白视为专用走廊：建议宽度至少 48px（线到两侧阻挡物各至少 24px）。跨域边从明确端口离开，垂直穿越边界，并以显式 waypoint 固定在走廊中央；从不同高度进入走廊，避免共享同一段。边界上的说明不要作为长边标签：短动作词可以放在线上，长说明应进入节点卡片或放在独立 label chip。

每次几何或容器调整后运行：

```bash
python3 skills/draw/scripts/check_geometry.py path/to/diagram.drawio
```

脚本检查未压缩和标准 deflate 页面，报告非端点节点/文本标签穿越、长边标签、无 waypoint 的跨域边或跨度超过默认 240px 的边，以及低于默认 24px 的净空。每一段必须显式为水平或垂直；否则脚本停止并要求补 waypoint，而非猜测 draw.io 的自动弯折。它仍无法判断富文本真实字宽或曲线；这些留给视觉验收。

## 双尺度验收

在 draw.io 或浏览器截图中逐项确认：

1. 在约 35–45%：整页未裁切左右域，主方向和域边界清晰。
2. 在约 65–80%：文字可读，容器标题、标签、虚线边界与关键走廊均无重叠。
3. 脚本通过，或对每项告警有可解释的、记录在案的例外。
